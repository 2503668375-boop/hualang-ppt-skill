# 表格与结构化信息 V11

表格用于交叉查询、同口径比较、日程、评价和办理信息。单行关系、推导、长段解释优先使用开放图文或活动版式。

## 1. 六类表格样式

| style | 适用内容 | 视觉处理 | 场景示例 |
|---|---|---|---|
| `editorial` | 综合明细、资料清单、查询 | 浅紫表头、细分隔线、克制的交替行 | 内部附件、家长办理清单 |
| `comparison` | 目标/实际、方案 A/B、前后对照 | 首列稳定、重点列浅紫、数字右对齐 | 招生复盘、课程比较、费用审议 |
| `matrix` | 多字段交叉、掌握情况、课程矩阵 | 表头与首列强化，可加轻竖线 | 复习诊断、课程适配 |
| `schedule` | 日期、时间、事项、责任、地点 | 日期列紧凑，事项列加宽，节点清晰 | 校务节点、家长会、招生办理 |
| `rubric` | 评价维度、等级、判据、反馈 | 判据列加宽，等级列居中，重点行强调 | 教案、作品评价、课堂反馈 |
| `checklist` | 材料、动作、责任、状态 | 状态列居中，文字与底色共同表达 | 家校协同、报名材料、落实清单 |

六类样式共用品牌色、网格和表头语义。差异服务于阅读任务，避免只换颜色。

## 2. 自动排版规则

`scripts/hualang_tables.py` 提供 `plan_table()` 与 `draw_table()`：

1. 根据列类型、表头和单元格内容分配列宽。长文列获得更大权重，数字和日期列保持紧凑。
2. 按实际列宽估算换行，逐行计算高度；表头同样参与测量。
3. 内容超过页面高度时按完整数据行续页，每页重复表头并保留相同列宽。
4. 数字右对齐、文本左对齐、日期与状态居中，表头跟随所属列类型。
5. 重点行、重点列和合计行使用浅底、字重和细线共同表达，不能只依赖颜色。
6. 不自动缩小字号。单行过高、字段过多时明确报错，返回内容重组或拆列。
7. 不合并、拆分或嵌套单元格；续表标题添加“（续）”，期间、单位和范围就近保留。内部原始出处留独立底稿；教学与对外引用按实际用途保留。

### 列类型

| type | 对齐 | 宽度策略 | 示例 |
|---|---|---|---|
| `text` | 左 | 中等 | 工作项、课程、责任部门 |
| `longtext` | 左 | 较大，允许两行及以上 | 原因、判据、家庭动作 |
| `number` | 右 | 紧凑，保留千分位与单位 | 人数、费用、比例 |
| `date` | 中 | 紧凑且不随意截断 | 日期、学期、时间段 |
| `status` | 中 | 紧凑，保留完整状态文本 | 已定、待确认、进行中 |

### 页面容量

- read：表内 19px，适合会后阅读与明细查询。
- near：表内 23px，适合家长会与近距投影，减少行列并放大重点。
- far：表内 26px，只保留极少字段与关键行；复杂办理信息另做 read/near 页。
- 超过 8 列时先拆成“主比较 + 补充明细”或按字段分组续页。
- 长表优先续页，不压缩到无法阅读；行内长文超出单行可容纳高度时改写或拆成两行语义内容。

## 3. 输入规格

```json
{
  "layout": "table",
  "title": "开放日费用比较",
  "lead": "B场新增费用集中在物料与师资",
  "context": "模拟资料 · 非学校实绩；金额单位为元",
  "table": {
    "style": "comparison",
    "caption": "两场费用采用相同科目与比较基准",
    "columns": [
      {"label": "费用科目", "type": "text", "weight": 1.4},
      {"label": "A场", "type": "number"},
      {"label": "B场", "type": "number"},
      {"label": "差额说明", "type": "longtext", "weight": 2.0}
    ],
    "rows": [
      ["场地", "6,000", "6,000", "两场一致"],
      ["物料", "2,000", "4,000", "新增60组家庭资料与物料"],
      ["师资", "4,000", "5,000", "增加体验课教师支持"],
      ["合计", "12,000", "15,000", "增加3,000"]
    ],
    "focus_columns": [2],
    "focus_rows": [2],
    "total_row": true,
    "source": "来源：本次模拟报价；正式采用前须替换为已核实资料"
  }
}
```

内部汇报通过整稿构建器生成时，`table.source` 保存到独立报告的 `source_records`，不画进PPT。观众需要的模拟性质、期间、单位与范围使用 `context`、表头或具体数据标签，不借来源行显示。

`rows` 也支持对象数组，键名与 `columns.key` 对应。`focus_rows` 使用数据行 0 基索引，不含表头；续页时自动映射到所属页。

## 4. 表格替代关系

- 5 年趋势：折线或同尺度点线，表格保留明细。
- 2–5 项同口径比较：`bars` 或 `comparison`，需要查精确值时附表。
- 3–5 个阶段：timeline 或 process，日期与动作不必强行塞入表格。
- 教案活动序列：`activity`，保留任务、预期回应与调整的可读空间。
- 学生推导与作品批注：`lesson` 或 `evidence`，让主对象占据页面中心。
- 大量文字说明：拆成判断、证据和条件，避免单个单元格承载整段文章。

## 5. 验收清单

- 只读表头与首列，能否理解字段和比较方向。
- 每个数字是否有单位、期间、必要分母及范围；原始出处能从底稿追溯，是否显示按场景规则处理。
- 同列小数位、千分位、日期格式与状态词是否一致。
- 长文是否换行，行高是否足够，末行是否被裁切。
- 续表是否重复表头，列序与列宽是否稳定。
- 重点行、重点列是否有明确业务含义，是否过度强调。
- 灰度查看时是否仍能读懂重点与状态。
- 表格是否保持原生可编辑，是否使用简单表头与无合并单元格结构。
