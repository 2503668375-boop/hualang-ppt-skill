# 制作与交付流程

目标是复用已经可靠的品牌和原生对象操作，把时间放在本次内容与页面上。优先用当前可用的原生演示工具，沿用同一工作文件，不混用多套生成流程。

## 生产入口

1. 环境和保存位置在任务开始时检查一次；同任务已核验且未变的条件直接复用。桌面环境用 `load_workspace_dependencies` 找到随附运行库。已有文件先读其内容和相关实际页面，避免错把模板中的案例当成任务材料。
2. 本技能的 `assets/reference.pptx` 是品牌底稿，`assets/source-original.pptx` 是保留的原始模板。新稿从品牌资产与本次逐页内容起稿，不复制上次案例的主题。旧稿编辑保留正确的本次内容和原生对象，按反馈定点修改。
3. 本地可用 `@oai/artifact-tool` 时，采用 [hualang-kit.mjs](../scripts/hualang-kit.mjs) 复用封面、页眉、文字、图片、表格与图表。API与运行方法见[制作API](production-api.md)。辅助库负责稳定样式，不决定内容、页数和布局组合。任务开始时确认可用字体；需要替换时通过 zhFont/latinFont 参数统一设置，再检查换行，不修改辅助库源码。
4. 若当前平台采用其他原生演示工具，按相同品牌与对象要求操作，不为换工具改变用户的产物。不要把文字、表格和图表栅格化来掩盖编辑问题。

完成后按[固定封面](cover-layout.md)核对三个字段，并对题名执行 `scripts/check_style_contract.py`。课堂和家长页分别使用对应场景入口，其他布局按实际阅读任务扩展；不默认全部调用普通正文页。

## 内容与版面

按逐页内容选主体构图。通栏比较表、图与就近说明、单主图批注、流程、时间轴、作品对照均可使用。标题区和品牌稳定，主体随问题改变；同一组可比数据保留列序与尺度。

绘制数据图前核对分母、数值轴、单位、统计期和系列。数学关系使用数值坐标。原生图片保持比例，不能裁掉关键证据。图像不足时，先看是否可以用原生关系图说明；需要情境图才生成并标示属性。

## 文件检查

候选稿导出后，运行当前环境的文件与原生对象检查，并从最终文件重新渲染。验证要求来自本次任务，例如指定表格、数据图和页数；不能只按已生成的东西反推要求。

随后执行[任务、文案、排版与美化检查](review.md)。修复后只回看改动页及关联项。品牌或全局文字改变时看全稿。若PDF转换缺字，修复字体或提供与最终页面一致的图像预览，并明确预览与可编辑PPT的区别。

输出文件保留用户主题与容易辨认的版本名。只将最终交付放入成品目录，候选、渲染和检查记录留底稿。核对用户指定硬盘确实挂载、文件确实保存；未做的应用放映测试不能写成完成。

题名检查报错由制作者修正。用户给定的正式题名按原要求保留并记录例外，不以技术报错中断可继续完成的工作。
