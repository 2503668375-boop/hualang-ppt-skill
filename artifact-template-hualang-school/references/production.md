# 制作与交付流程

目标是复用已经可靠的品牌和原生对象操作，把时间放在本次内容与页面上。优先用当前可用的原生演示工具，沿用同一工作文件，不混用多套生成流程。

## 生产入口

1. 常规整稿优先使用 V11 统一编排层。按[页面规格](deck-spec.md)把本次主题或资料转换为 `deck-spec.json`，运行 `scripts/hualang_build.py` 生成完整稿与构建报告。该入口内置八类场景、自动分页、六类表格、续表、固定首尾、课堂反馈页和可选点击出现；表格细节见[表格系统](table-system-v11.md)。
2. 环境和保存位置在任务开始时检查一次；同任务已核验且未变的条件直接复用。已有文件先读其内容和相关实际页面，避免错把模板中的案例当成任务材料。
3. 本技能的 `assets/reference.pptx` 是品牌底稿，`assets/source-original.pptx` 是保留的原始模板。新稿从品牌资产与本次逐页内容起稿，不复制上次案例的主题。旧稿编辑保留正确的本次内容和原生对象，按反馈定点修改。
4. 统一编排层未覆盖的特殊学科图形、复杂图表或定制交互，沿用 [hualang-kit.mjs](../scripts/hualang-kit.mjs) 或 [python-pptx 生产通道](python-production.md)精修。宿主已有 `@oai/artifact-tool` 时可使用 JS 通道；它不是本技能要求从公共 npm 安装的依赖。API与运行方法见[制作API](production-api.md)。
5. 两条底层通道都保留品牌、原生可编辑对象和保存前检查。选择主通道后沿同一工作文件完成，避免重复导入导出造成媒体、图表工作簿或动画丢失。

单一场景按整稿设置默认用途，混合场景用`sceneMode:'mixed'`逐页传`purpose`；不要把所有场景藏在一个固定report/summary包装函数里。逐页简记读者动作、具体主对象与组件作用，场景差异由实页证明。

完整稿完成后按[固定首尾](cover-layout.md)核对封面三个字段、无重复标题及原封尾，并执行 `scripts/check_style_contract.py`。用户明确仅要一页或数页正文时，对现有文件使用 `python scripts/check_style_contract.py 正文.pptx --content-only`；该范围检查所有现有正文页的题名及页眉位置，不要求首尾、署名日期，不为通过检查增页。校徽、金线、背景及内容和视觉仍须实页核对，该参数不构成视觉认证。课堂按数学、文本或观察对象选择入口，家长成果按数据、作品与支持选择入口，开放招生活动按沟通环节选择照片、课程比较或办理信息，其他布局按实际阅读任务扩展；不默认全部调用普通正文页。

## 跨工具的最小实现

[样式契约](../assets/style-contract.json)的`implementation`给出单位、字体、场景字号和正文边界，`cover/closing`给出首尾字段与安全区；它们是跨工具共同依据，不依赖某个制作库。逻辑画布为1280×720，按模板映射1px=9525EMU=0.75pt，24px字号对应18pt；不要把逻辑像素当成PowerPoint点值，或按预览截图的像素尺寸另算页面。

- 完整稿保留固定首尾，封面默认主标题、汇报人、日期三个字段；副题仅在有独立范围或用户要求时使用。封尾保留原底图和安全区，局部单页沿用正文框架。
- 常规页保留左题、右徽、金线、近白底及既定色彩职责；V11远距出血页按[场景视觉语法](scene-visual-grammar.md#整页出血对外专用)保留金色校徽与原始首尾，使用其页眉、金线和页码例外。用实际可用字体统一替换缺失字体，再核对最终换行和字形；字号以[场景视觉语法](scene-visual-grammar.md)的档位为起点，核心级差可参考1.2，并按实际可读性调整。
- 文字、表格、数据图和需修改的关系节点保持原生可编辑。数值图按真实坐标、共同尺度及单位绘制；图片保留比例和证据，整页截图不算等价实现。
- 模拟数据、原创题例和拟议安排在主体对象近旁标明属性；图表被单独截取时仍能看出其性质，不能只在全稿页脚声明。

品牌几何和单位按契约；主体坐标按12栏网格与内容负载安排（主要分区优先参考 x=48+100n，区内对象允许按内容定位），字号以档位为起点。实现后仍按实际保存文件核对品牌、对象、数据与页面，不以字段齐全推定质量。

## 内容与版面

从[对象与场景](scene-layouts.md)确定核心回答、证据顺序和阅读动作；随后安排图片角色与必要留位。材料先写足影响判断的比较、解释、过程和条件，视觉突出本页重点，不把“内容丰富”理解为每页同样多字。素材处理见[图片与留位](image-planning.md)。

内部留阅、专项分析与阅读型家长材料先完成[实质内容与容量](content-depth.md)，再确定页序和空间；底稿保留主问题、原材料、派生计算、解释/建议及其条件。介绍与演讲按讲述单元组织，记录本次必答事项、具体主体、必要解释和事实条件。课堂与教案按[教学设计](teaching-design.md)保留目标、完整对象、推理、活动、预期回应与反馈。介绍的简短程度由用户范围与使用时长决定，用足以说明处理作用的局部例子，不把整套案例和审查规则搬上屏。这些底稿记录不进入观众材料。

确定页序前按[内容核对](workflow.md#内容核对)对照每页答案和重复素材，先合并同义复述，再分配版面。遵守用户指定页数，保留理解与使用所需内容；未指定时不先凑页数。阅读材料需要的完整段落与数据字段不删，短介绍不为填满版面补无关内容；图表按实际负载缩放，不先固定大图尺寸后压缩内容。

按逐页内容选主体构图。通栏比较表、图与就近说明、单主图批注、流程、时间轴、作品对照均可使用，其作用应落实到可查数据、具体词句、先后关系或作品变化。若页面仍需逐块读完同一组文字才能理解，增加色块、编号和图标没有形成新的主体；回到材料关系重组。标题区和品牌稳定，主体随问题改变；同一组可比数据保留列序与尺度，必要复现用于核对和推理。

内部报告起稿先读[内容与版式选择](report-layouts.md)，底稿登记读者动作与主证据。`addPage`只提供品牌框架；`addReportPage`的历史分区供兼容，不要求证据下方固定再放备注块。新稿可以在完整正文区开放组织，不能循环调用同一排卡片函数覆盖全稿。按内容选局部组件，不能先画框再填材料。

中心支撑、包含、递进或复合图文参考[构图库与实际样张](layout-atlas.md)。辅助库新增`hubSpoke`处理中心与外围的关系、说明和可选连线；其他构图按当前原生工具组合，不增加一套按页轮换的整页函数。缺少该运行库时依现有原生工具保留同样的内容、品牌和编辑要求，跨AI试用见[试用任务](other-ai-trial.md)。

序列辅助检查：

```text
python3 scripts/audit_sequence.py 最终稿.pptx --output 构图检查.json
python3 scripts/audit_sequence.py 最终稿.pptx 逐页清单.json --output 构图检查.json
```

清单兼容`{"slides":[{"slide":2,"family":"趋势主图","task":"追踪同口径变化","mainObject":"季度趋势","continuationReason":"如需保留同构，说明实际比较需要"}]}`；须覆盖全部正文页。`family`用于辅助检索，`task/mainObject`留给内容复核，不参与几何通过判断。输出中的`similar_pairs/panel_grid_pages/findings`指出复核位置，保留理由随发现输出。`ok`仅指文件清单结构有效，重复警告不能直接当失败，也不能忽略实页。

绘制数据图前核对分母、数值轴、单位、统计期和系列。数学关系使用数值坐标。原生图片保持比例，不能裁掉关键证据。图像不足时，先看是否可以用原生关系图说明；需要情境图才生成并标示属性。

## 底层稿件与检查范围

定制图形可用底层 `Deck` 与局部组件，但 `Deck.save()` 只保存文件并核对部分结构。它不会执行整稿规划、计算复算或人工内容审查。此通道从最后PPT运行 `audit_content_claims.py`，复算本次相关数值、回读完整任务及结论，再完成实际渲染；检查记录列出真正执行的检查与未测范围。统一入口的报告同样只能支持它实际检查的事项，不写“自动挡住错稿”。

## 文件检查

最终预览必须由最后保存的PPTX重新导入并渲染；部分运行库的内存直接渲染可能漏掉继承母版层，先比较保存文件与重导入结果。当前辅助库将相同位置的校徽与分隔线直接写入正文页，以避免跨渲染器漏继承层；正文底色和固定首尾仍按原模板，不同时叠加重复品牌层。

同一文件的实际预览若出现丢层、重影或空白，不以结构中“对象存在”抵消，也不挑选一张较好图宣布通过。可用另一实际演示引擎从最终文件导出交叉核对，统一声明所采用的预览来源与检查范围；未知原因如实保留，不为凑图无依据修改源内容。

`writeDraft`现在保存后调用`renderSavedDeck`，预览放入新的run目录，并记录源文件与图片摘要；成功只表示候选预览已生成，返回状态仍为`unreviewed`。补附件、动画或其他保存后处理改变了PPTX时，用`renderSavedDeck`读取最后版本，不重存有动画的文件。其他工具链同样记录最终文件与实际预览的对应关系，并按[审查记录](review-record.md)声明`renderEvidence`来源。

候选稿导出后，运行当前环境的文件与原生对象检查，并从最终文件重新渲染。没有可用的演示软件时，用 `scripts/mirror_render.py` 生成结构镜像看页面，按[无实际渲染环境时](#无实际渲染环境时)声明证据类型，不把镜像称做实际渲染。验证要求来自本次任务，例如指定表格、数据图和页数；不能只按已生成的东西反推要求。

随后执行[任务、文案、排版与美化检查](review.md)。修复后只回看改动页及关联项。品牌或全局文字改变时看全稿。若PDF转换缺字，先检查渲染环境的字体加载与替代，再重新渲染受影响页；缺字预览不能支持视觉通过。能生成真实页面图像时，明确预览与可编辑PPT的区别。

设计表现整改时，按[精修实页](design-craft.md)选择能覆盖实际缺陷的代表材料，保留同材料前后图。只有规则文字变化或组件名称增加，尚未验证出品改善。主制作流程与现有工具能完成时沿用，不为显得更新而增加另一套制作系统。

完整新稿与重做稿分别审内容、表达与场景、视觉和文件，使用[审查记录](review-record.md)绑定最终证据并关闭问题。`review_gate.py`的成功只表示可提交人工签收，不能代替实际读稿和实页决定；任何一项需要修改时继续修复。

输出文件保留用户主题与容易辨认的版本名。只将最终交付放入成品目录，候选、渲染和检查记录留底稿。核对用户指定硬盘确实挂载、文件确实保存；未做的应用放映测试不能写成完成。

题名检查报错由制作者修正。用户给定的正式题名按原要求保留并记录例外，不以技术报错中断可继续完成的工作。


## 无实际渲染环境时

先核对已有的目标应用、Office兼容渲染器或能重新导入PPTX的运行库，只使用当前可用路径。由最终PPTX打开/导入后导出的页面，记录为`saved_file_render`或`application_export`，并写明引擎与入口。它们能支持静态实页审查，仍不代表PowerPoint放映或投影已测。

若只能解析坐标、字体和文字后重画HTML/SVG，记录为`structural_mirror`；缺少来源则为`unknown`。镜像可辅助检查结构、清单和预期布局，无法证明最终文件的换行、字体替代、继承层或绘制效果。保留视觉项为`unverified`，不标为`ready_for_human_signoff`。可以交付候选稿及已完成的检查，让后续在可渲染环境中补查；不能将镜像改名为实际页面。

交付说明可写：“已完成内容与文件结构检查；当前预览为结构镜像，尚未核验最终PPTX的实际页面，需补做字体、换行和对象显示检查。”未完成的验证单独说明，不写入观众材料。

## 带动画的交付顺序

按题目登记揭示步骤→导出无动画基础稿→完成文件与视觉检查→对最终基础稿写入原生时间线→检查动画目标和静态状态。写入动画后不再用会丢失时间线的导入导出工具重存。静态渲染只用于查看页面，不能取代最终动画文件。

检查初始态答案隐藏、每步对象顺序、末态完整；有PowerPoint时实际放映。未安装PowerPoint时说明已做的结构/状态检查和未做的应用兼容性测试。可配点击预览辅助用户查看，不能把网页预览称为PowerPoint测试。

原封尾继承整页背景图，并叠加已核实培养目标及场合结束语。若平台检查只报告该页没有直接绘制对象，用 `check_template_package.py` 委托原检查器并核对封尾原图摘要；只记录这一明确的模板例外，其他错误照常失败，不加透明对象来凑检查。
