# 审查记录与证据绑定

记录承接[成品验收](review.md)中已经发生的读稿与实页判断。先有人判断设计、场景结构和学习负载，再填写记录；不能由导出脚本批量写入“通过”。`review_gate.py`只核版本、范围、证据文件和问题状态，不识别审美，也不检查教学是否充分。

沿用`schemaVersion:1`及现有字段，不增设设计评分、关键词匹配或组件配额。格式完整与内容达标是两件事。

## 从实际预览建立记录

`renderSavedDeck`或`writeDraft`返回的清单状态为`unreviewed`。以该清单为基础，保留真实路径与摘要，再补观察：

- `artifact.path/sha256`、`renderSourceSha256`绑定最后保存的PPTX；相对路径以审查记录所在目录为基准。
- `pages`覆盖本次`scope`，逐页保留`slide`、`render/renderSha256`，补`scene`、`subject`和`verdict`。`subject`写实际对象，如区间函数图与分类推理、匿名作答修订，不只写“两栏”或“有组件”。
- `gates`保留`content`、`expression`、`visual`、`file`四项，各自填写`verdict`与`evidence`。每条观察仍为`{"slides":[页码],"observation":"实际发现"}`。
- `issues`保留实际问题；没有发现时用空列表。未核验保持`unverified`，需修改用`revise`，不为让脚本退出0改成`pass`。

完整稿覆盖全部页，四项分别判断。局部修订可用`scope:[页码]`，未受影响的项目可用`not_applicable`并解释原因；局部范围不能称全稿重新通过。

## 观察要写设计与使用结果

先记录核心概论是否可见、材料是否成为主体、使用者能完成什么、教学单元的内容负载是否充分，再记录断行和文件等细节。不能以技术微修关闭了几个问题，推定整个设计成立。

例如发现课堂材料失效，应明确保留待改：

```json
{
  "gates": {
    "expression": {
      "verdict": "revise",
      "evidence": [{
        "slides": [7],
        "observation": "题目与答案可读，但所谓独立任务已同时显示答案，未呈现可观察的学生产出与错误后的处理，尚不足以支持本次课堂用途。"
      }]
    },
    "visual": {
      "verdict": "revise",
      "evidence": [{
        "slides": [7],
        "observation": "核心学习判断被压为灰色小字；主体仍是两组段落，函数关系没有借助可核对的表图或理由组织形成阅读重点。"
      }]
    }
  },
  "issues": [{
    "id": "lesson-07",
    "slide": 7,
    "area": "expression",
    "problem": "课堂用途与内容负载尚未由实际成品证明",
    "status": "open"
  }]
}
```

上例只展示问题写法，不是完整审查记录或所有课堂页的固定构图要求。实际记录补齐四项与本次全部范围。必要材料、概论和学习过程须据真实页面判断，不能通过出现相应词语自动认定成立。

## 声明预览的实际来源

顶层`renderEvidence`沿用以下结构：

```json
{
  "renderEvidence": {
    "kind": "saved_file_render",
    "engine": "实际引擎及可得版本",
    "entryPoint": "读取最终PPTX后导出页面的实际入口"
  }
}
```

| `kind` | 含义与可支持的结论 |
|---|---|
| `saved_file_render` | 演示引擎读取最终PPTX后渲染，可支持静态实页审查 |
| `application_export` | 演示应用打开最终PPTX后导出，可支持实际导出的页面范围 |
| `structural_mirror` | 解析坐标与文字后重画，只支持布局意图辅助核对 |
| `unknown`或缺字段 | 来源未核实，需补实际文件呈现证据 |

前两项须填写真实的`engine`与`entryPoint`，仍不等于PowerPoint放映或现场投影已经验证。后两项不能支持视觉与文件呈现通过；可保留已完成的计算、内容和原生对象检查，并说明待核范围。摘要只能绑定声明与版本，不能证明声明真实。

## 问题关闭与旧结论撤回

每个问题保留`id`、`slide`、`area`、`problem`、`status`；`area`仍用四项gate键名。未解决为`open`。完成修复并看过对应新实页后，才改为`fixed`，补`resolution`和当前页的`checkedRenderSha256`。修复说明写实际改变，如概论提升为主阅读入口、补上理由与独立任务、将比较对齐到同一尺度，不只写“已优化”。

自动几何提示由实际页面裁定；必要稳定题域或合理叠层可以保留并写明用途，不把真实缺陷降为建议。工具不保存修复前历史，同一个摘要也不能替代前后页面观察。

用户否定后保留旧记录作为历史，并创建新记录撤回当前视觉及受影响的表达与场景结论；任务覆盖或教学负载不足时重审内容。记录新发现和待改项，旧的`pass`不再作为本次交付依据。整改用同材料前后实页证明变化。独立AI审查不等于用户认可，不能以多名AI一致同意反驳用户反馈。

文件改变后绑定最后版本，局部修复只复查受影响范围；全局内容、品牌或样式变化看全稿。预览替换、补附件或添加动画后，不得继续拿旧版本图作为最终文件证据。

## 一致性检查与交付判断

```text
python scripts/review_gate.py 审查记录.json --output 审查状态.json
```

`return_for_revision`表示记录、证据或未关闭问题仍需处理。`ready_for_human_signoff`只表示这些条件齐全；制作者仍须依据实际内容、场景、设计和文件判断是否交付。脚本不能认证美观、理解效果或教学成效。

若用`audit_rendered_pdf.py`等工具量测实际字形，保留其测量范围；无几何发现也不等于视觉通过。审查记录、工具输出和来源路径独立保存，不进入观众材料正文、页脚、附页或备注。
