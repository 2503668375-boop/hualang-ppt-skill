# V8完整性与思考逻辑审查

审查日期：2026-11-06。对象为V7现行技能、相关参考、制作辅助库、检查脚本及既有验证记录。以下区分规则修订、文件检查与实际场景验证，不将参考文件数量、示例页数或自评得分视为完整性证明。

## 结论

现行技能已覆盖内部经营与管理、教师教案、学生课堂、练习复习、家长成果、招生说明、对外演讲及双语材料，品牌与原生对象的基本约束也较完整。主要缺口在这些环节的连接：材料怎样支持判断，教学怎样从答案走到理解和迁移，密度怎样保住必要关系，维护验证怎样反映真实使用。继续增加场景名或组件清单无法单独解决这些问题。

本轮沿用已确认的左标题、右校徽、金色分隔线与近白底。丰富排版发生在正文区，按材料、推理和观看动作选择组件。密度以可对照的完整内容与必要条件判断，不以字号更小、框更多或题目更难作为成功标准。

## 发现与处理

| 发现 | 对结果的影响 | 本轮处理与验收依据 |
|---|---|---|
| 起稿已要求读者、用途和证据，但从事实到解释、从解释到动作缺少明确核对 | 数据与结论各自存在，却可能相互不支持 | `workflow.md`增加“材料→事实→判断→取舍/动作→页面”的反向追溯及一个有口径的具体例子；`reporting-method.md`明确观察、解释和建议分别成立 |
| “教案有目标、课堂有答案”容易被当作教学完成 | 只回忆定义或套用刚示范的步骤，仍可能得到形式通过 | `review.md`增加完整对象、关键理由、条件/反例、方法比较、独立迁移、错误反馈的检查；专项教学规则另行细化，实际新课件须验证 |
| 密度要求与舞台简洁要求分散，容易被理解为每页必须同样密 | 课堂可能缩字挤满，演讲可能变成密表；也可能借留白丢失依据 | 工作流和验收统一以“同时核对的关系是否完整”判断；聚焦页结合相邻讲述单元审查，课堂同时看初始态和完整末态 |
| 验收参考按V5、V6、既有教学及连续稿重复追加 | 容易漏查或只按最后一段执行，关键关系被版本补丁淹没 | `review.md`合并到任务、推理密度、事实、页面、联排、状态和维护验证，保留原有实质检查 |
| 内部质量报告对可比样本、任务难度与因果解释的提醒尚不足 | 把均分变化归因于措施，把群体变化误认为学生进步 | `internal-report.md`补样本、题目、评分、匿名作答及复测条件；测算按关键假设复算，未授权职责与时点不虚构 |
| 组件索引以版型为主，概念辨析、文本论证和科学建模不够显性 | 教学被收缩成数学解题或普通两栏图文 | `component-index.md`增加概念边界、方法比较、史料/观点证据链、实验/模型检验，明确所需具体对象与不适用情形 |
| 表格容易成为流程、教案、方法与归纳的默认载体 | 内容虽完整，阅读动作和关系仍被统一行列压平 | 工作流、验收、方法、内部汇报及组件参考明确小组件与实际对象优先；仅真实行列查数或多字段核对时采用表格，示例据此重排并保留解释与条件，不设数量配额 |
| 输入有来源时容易只审排版和自己改写的部分 | 原材料中的错误案例、百科知识、题解或过时条件可被原样包装进成品 | 工作流明确来源不等于事实可靠；验收加入最终内容正确性关卡并连接专项参考，问题须给位置、依据、建议、影响和状态，重要未解问题不称已可授课或正式采用 |
| 安装说明包含软件自动发现机制的绝对表述，并依赖固定外链解释 | 软件变化时可能错误承诺“安装即能使用” | `getting-started.md`改为读取当前版本与资产、确认本轮可调用；保留仓库入口，不把本地目录误称插件商店产品 |
| 场景表与部分工具默认值未完全一致 | 家长现场页可能继承阅读稿字号，表格字号可能忽略场景profile | `addSchoolScene`支持显式用途，表格默认值跟随页面profile；独立导出后读回OOXML，家长/课堂的默认值及显式覆盖均通过 |
| 题名自动检查与英文、合理学科短语存在潜在冲突 | 内容可能为满足检查器而改变正常题名 | 正常中文学科短语、14词英文及长中文题名经实际入口与保存后检查通过；长中文提示实看，自动口播/问句仍被拒绝，用户题名保留豁免 |
| 序列检查对相邻续页和四页循环的处理不一致 | 为避免ABAB命中而强行改教学版式，或仅修改family标签 | 重复版式改为实看提示，清单结构仍严格检查；实际连续四页及ABAB情形通过，重复/缺漏页码分别失败；续页理由仍需从真实内容解释 |

## 验证矩阵

这是按改动风险选择实际任务的依据，不要求每轮机械重做所有场景。V7既有证据仅说明其当时产物；V8的新结论以本轮保存文件和验证记录为准。

| 场景 | 有意义的测试任务 | 需要看到的证据 | 不能据此推定 |
|---|---|---|---|
| 内部经营/费用 | 同口径目标与实际、真实待审事项或既定多场安排 | 判断可追到数据，分项与合计可复算，拟议/已定及条件保留 | 原因已获因果证实，或资料缺项赋予新的审批权 |
| 教学质量管理 | 同标准群体表现、能力项及匿名作答 | 区分群体/个体，解释有证据或保留假设，支持与复测针对错误 | 只凭均分变化证明措施有效 |
| 教师教案 | 给定年级、学科、基础及课时的完整课程 | 目标、活动、预期回应、证据、反馈与调整可对应，时间含独立作答 | 仅一张活动表证明完整教学设计或真实耗时 |
| 初中课堂 | 从概念建立到常规应用及条件变化 | 完整对象、示范、易错诊断、独立短任务及答案，后排所需信息可读 | 高中样例通过便覆盖初中，或页数证明授课效果 |
| 高中课堂 | 有边界、分类或方法比较的连续单元 | 推理完整，图式条件一致，反例有辨析作用，独立迁移及反馈可执行 | 只增加计算量或使用难题即证明教学深度 |
| 文本/史料/科学 | 给定材料的解释，或装置—变量—数据—模型任务 | 证据定位、理由、限制与其他解释；图/表/文连通 | 数学解题页通过便证明其他学科专业能力 |
| 国际课程/双语 | 给定课程、层级与实际考试范围的学科任务 | 语言支架服务学术任务，指令词与正式评分要求有来源 | 英译课件等同国际课程，未知考试年可凭经验补官方要求 |
| 家长成果 | 同口径数字及匿名作品前后对照 | 数据、作品局部、解释与学校/家庭支持，现场和阅读版事实一致 | 校园照片证明学习成效，或模拟数据成为本校实绩 |
| 招生与对外 | 有当期条件及具体事件的课程/体验说明 | 主张、照片或作品、适用条件及下一步，聚焦页有相邻证据 | 历史活动、第三方材料或生成情境成为当期承诺 |
| 品牌与工具 | 按受影响入口制作并保存小样 | 固定首尾、母版、字体、默认表格字号、原生对象及相对引用 | 技术检查代表内容、审美或应用兼容性都通过 |
| 连续稿与揭示 | 完整连续单元及代表性多步骤页面 | 逐页/联排实看，任务—时间—状态对应，初始/关键中间/末态一致 | 多份短稿相加证明长稿，静态图或网页点击证明PowerPoint放映 |

## 检查结果与边界

本轮文档修订后，仓库相对链接与基础包结构检查通过。该检查可识别缺失文件、失效相对引用及基本PPTX部件，不能评价教学正确性与页面质量。具体新产物、工具运行及实际渲染以本轮独立验证记录为准。

工具行为由独立测试实际创建并导出6页表格小样及3页纯组件小样，再读最终文件，8项测试通过，见 `tests/test_tool_behavior.py` 及其原生制作夹具：

- 家长/课堂默认表格24px/23px在保存后分别为18pt/17.25pt；显式29px/26px覆盖分别为21.75pt/19.5pt。正文28px/25px及显式31px覆盖同样保存正确。
- “先秦文化”、14词英文题名、长中文学科短语通过；空题名与“先读材料再比较证据”“如何理解模型”“本页讨论证据”等自动口播被拒绝；用户提供题名的语义豁免仍可用。保存后首尾/题名合同通过，长中文仅给复核提示。
- 四页同一对象连续推理附理由时通过；无理由重复产生人工复核提示；清单重复与缺漏正文页码各自失败。该小样证明检查器行为，没有将占位教学材料当成课堂验证。
- 从保存的PPTX重新渲染并实看4页正文，长英文标题处于页眉安全区，未侵入校徽；默认字号与显式覆盖均可辨。小样只用于接口与文件回归，完整教学密度由实际课程单独检验。
- 正文品牌改为直接原生对象后，原7项回归继续通过；新增逐页核对两份小样的校徽与金线，每张正文页直接对象各1个，实际所属版式/母版继承链均无重复。保存后重新导入并渲染表格页与纯组件页，品牌显示完整；原始封面与封尾仍通过既有合同检查。未把母版关系中列出的其他兄弟版式误计为当前页的继承对象。

运行测试时从当前环境发现Node及原生制作库，以 `HUALANG_NODE`、`HUALANG_NODE_MODULES` 传入。未配置运行库时该组原生导出测试明确跳过，不报告为通过。临时PPTX与渲染留在仓库外；运行库和本机路径不进入公开包。

本审查没有重新核实学校当期招生、课程资质、收费、师资或成绩；这些仍按每次实际任务核验。现有图片的公开可见性不代表无限使用许可。尚未进行的Microsoft PowerPoint应用内放映、真实教室投影和授课效果评估均保留为边界，不把规则修订写成已完成的现场验收。

本轮教学题例为原创，业务数据为公开示例中的模拟数据，分别按题解与口径复算；不据此声称已核验全部教材、所有外部案例或百科事实。最终正确性审查须覆盖本次真正进入成品的输入及改写，发现的问题与建议作为独立说明交付，不能把审查日志混入观众材料。

对于尚无实际样例覆盖的学科、考试局或辅助功能，不作“全学科已验证”“完全无障碍”等概括声明。后续应由真实任务发现缺口并作针对修订，避免继续累积与结果无关的流程和文件。
